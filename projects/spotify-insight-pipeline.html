Spotify Insight Pipeline

An evidence pipeline for a product decision: which customer problems deserve investigation, and how much confidence should a team place in the ranking?

The product problem

A large review dataset can produce an impressive chart without a trustworthy product recommendation. Topic labels are judgments, review volume is not the same as harm, and a priority score can hide uncertainty. I wanted to connect raw feedback to a recommendation that a reader could inspect, challenge, and trace back to the original reviews.

The approach

I used a Codex-assisted workflow to define and review the pipeline, Jev for bounded language-classification tasks, Python and SQL for data preparation and arithmetic, and local Qwen for issue names and recommendation drafts. The run ingested 660,622 source rows and completed classification for 244,582 original reviews. The dashboard publishes saved findings and selected evidence; visiting it does not trigger another model call.

PRODUCT & SYSTEM DECISIONS

Use different tools for different kinds of work

Jev handles bounded interpretation. Qwen drafts language locally. Python owns scores, membership, validation, caching, and checkpoints. VADER supplies a separate sentiment signal; it does not enter the severity-sum ranking.

Treat evaluation as a diagnostic

The frozen 50-review test had 68% topic agreement and 92% intent agreement with the original human labels. Those are agreement measures, not an adjudicated accuracy claim. The separate blind task exposes disagreements without treating a second prediction as ground truth.

Show sensitivity before making a roadmap call

Usability led the baseline by only 4.4% over playback. Excluding review-flagged records reversed their order, although that exclusion has its own bias. The recommendation became: investigate usability and playback together before allocating next-quarter effort.

Make long runs resumable and inspectable

SQLite stores completed IDs and processing state. Exact-text reuse is tied to matching model and prompt settings. Code validates quoted evidence and preserves original review IDs rather than asking a model to invent totals.

What the work shows

The completed subset contains 244,582 classified originals and 15,825 complaint/cancellation reviews used in the baseline ranking. Completion depended on processing stage and intent, so findings describe this subset rather than the full review population. The live dashboard connects priorities, recommendations, and selected source evidence.

A defensible product recommendation needs both a signal and an explanation of what could change the decision.
